# 移植原理与关键取舍

## 1. 为什么是「重新托管」而不是「重写」

先看清目标形态，这一步决定了后面所有策略：

`Todo清单.exe` 有 215 MB，但它**不是自研代码** —— 是改名后的原版 Electron
运行时。用 Ghidra 逆向它没有任何意义。真正的应用逻辑在 `resources/app.asar`
里，而它是 JavaScript，**本身就是跨平台的**。

所以正确做法不是把 exe 逆向成 Linux 程序，而是：

```
官方 Linux 版 Electron 43.4.0（换掉底层的运行时）
  + 原封不动的 app.asar 与 app.asar.unpacked（应用代码）
  + 一处 26 字节的 asar 补丁（修 Linux 上缺窗口按钮的缺陷）
  = 可用的 Linux 应用
```

`app.asar` 的 290,483,523 字节**没有被重写**，只做了一次等长字节替换。

## 2. 为什么不该用 Ghidra

Electron 应用的「逆向」本质上是对 electron-builder 打包产物的**解包**，
不是对机器码的分析。本项目实际用到的工具是 `7z` + 一个自写的 asar 解析器，
Ghidra 在这里没有产出。

（REA 的静态 JS 分析工具在**高度压缩的 webpack 单文件**上也基本失效 ——
`require("electron")` 被 webpack 编号别名替换成 `r(165).BrowserWindow`，
静态解析追不到，实测 `browser_windows: 0`、`ipc: 0`、`modules: 0`。
真要读代码需要先反压缩。）

## 3. 为什么不能打成 AppImage（重要）

应用内置了 `electron-updater`，其 Linux 分支是 `AppImageUpdater`：

```js
if ("win32" === process.platform)      _ = new NsisUpdater;
else if ("darwin" === process.platform) _ = new MacUpdater;
else { _ = new AppImageUpdater; ... }
```

- **普通安装（pacman / 手动）** → `APPIMAGE` 环境变量未定义 →
  日志 `APPIMAGE env is not defined` → **更新器主动跳过，保持安静** ✅
- **打成 AppImage** → AppImage 运行时**会设置** `APPIMAGE` →
  更新器**被激活** → 向 `https://updatetodo.evestudio.cn/newer` 请求 →
  官方只发布 Windows/macOS 产物 → **必然 404 失败** ❌

**结论：pacman 包反而是更稳定的形态。** 除非把更新源改指到自建仓库
（那需要再打一个 asar 补丁改 `app-update.yml`），否则不要启用自动更新。

## 4. 为什么在 Arch 上选 pacman 本地包

| 方案 | 结论 |
|---|---|
| **pacman 本地包** | ✅ 推荐。原生、卸载干净、依赖自动处理、`pacman -Qo` 可溯源 |
| AppImage | ❌ 见上节 |
| 手动装到 `~/.local` | ⚠️ 可用（`scripts/install-user.sh`），适合快速试，但不进包管理 |
| 从源码重建 | ❌ 没有源码，上游只发二进制 |

### 打包的两个硬性约束

1. **`options=('!strip')`**
   makepkg 默认会 strip 二进制，而 **Electron 主程序 strip 后会损坏**。
   Arch 官方 `electron` 包的 PKGBUILD 同样禁用 strip。
   同时禁用 `!debug`（Electron 的调试符号没有意义且体积巨大）。

2. **装到 `/opt/todo-list` 而不是 `/usr/lib`**
   整个目录是自包含的运行时（含自己的 `.so`、`locales/`、`resources/`），
   按 FHS 惯例放在 `/opt`。命令入口用 `/usr/bin/todo-list` 符号链接。

### 依赖是怎么定出来的（不是猜的）

```bash
# 1) 取直接依赖（DT_NEEDED），注意 readelf 输出会跟随 locale
objdump -p todo-list | awk '/NEEDED/{print $2}' | sort -u

# 2) 映射到 Arch 包
ldconfig -p | awk -v s="$soname" '$1==s {print $NF}'
pacman -Qoq <库路径>        # 注意：-q 直接出包名，不加 -q 需要解析 "is owned by"
```

得到 34 个直接依赖 → 23 个 Arch 包：

```
alsa-lib at-spi2-core cairo dbus expat glib2 glibc gtk3 libcups libgcc
libx11 libxcb libxcomposite libxdamage libxext libxfixes libxkbcommon
libxrandr mesa nspr nss pango systemd-libs
```

`libffmpeg.so` 是随包自带的，不算系统依赖。

> 用 `ldd` 会得到 93 个库，其中大部分是传递依赖，不该写进 `depends`。

### PKGBUILD 里的一个坑

fakeroot 环境下 `cp -a` 会尝试保留属主，某些文件系统上直接 `EINVAL`
导致 makepkg 中止（`cp: 无法保留...的所有权: 无效的参数`）。
必须改用：

```bash
bsdtar -C "$srcdir/..." -cf - . | bsdtar -C "$pkgdir/..." -xf - --no-same-owner
```

既能保留权限位（可执行位很关键），又不碰属主。

## 5. 排查过程中排除掉的假设

「应用闪退」问题的排查中，以下假设均被实测**否定**：

| 假设 | 否定依据 |
|---|---|
| Chromium 沙箱被内核限制 | `unprivileged_userns_clone=1`，`apparmor_restrict_unprivileged_userns` 不存在，`chrome-sandbox` 755 也能走 userns |
| X11 与 Wayland 冲突 | 强制两种平台**都能走到「主窗口已显示」** |
| GPU 驱动崩溃 | 日志里的 `GPU process exited exit_code=139` **只在我的沙箱里出现**（无 `/dev/dri`）；用户真实桌面会话下完全没有 |
| 数据目录/权限问题 | `~/.config/todo-list` 正常创建，DB 正常初始化 |
| 启动方式（菜单 vs 终端） | `gtk-launch`（桌面菜单同款机制）也能正常拉起 |

**最终定位是应用自身的代码缺陷**（缺窗口按钮），
以及一个行为误解（「闪退」其实是单实例锁 + 缩到托盘）。

## 6. 关于「闪退」的澄清

关闭窗口**不是退出**：

```js
Xe.on("close", async e => {
  e.preventDefault();                    // 拦下关闭
  const t = await a();                   // 弹窗询问
  if ("quit" === t) { app.quit(); }
  else { dt.set("winBounds", Xe.getBounds()); Xe.hide(); }   // 缩到托盘
});
```

`window-all-closed` 才 `app.quit()`，但「隐藏」不算「关闭」，永不触发。

因此**再次从菜单启动会因单实例锁立刻退出**，窗口不出现 —— 用户感知为「闪退」。
应用其实一直在托盘里运行。

托盘菜单（非 macOS）：

```
打开Todo清单        ← 点这个恢复窗口
添加日历小组件
添加列表小组件
──────────
退出                ← 只有点这个才真正退出
```

## 7. 与 Windows 版的差异

| 项目 | Windows | Linux |
|---|---|---|
| 运行时 | 自带 215 MB Electron | 官方 Linux Electron 43.4.0 |
| 窗口边框 | 无边框 + 自绘标题栏 | 同上（补丁后） |
| 托盘图标 | `tray.ico`（代码实际用 `tray.png`） | `tray.png` |
| 显示桌面钩子 | `lib/showdesktop.node` | 不加载 |
| 更新器 | NsisUpdater | AppImageUpdater（未激活） |
| 小组件/悬浮窗 | 完整可用 | Wayland 下不可用（XWayland 下可用） |
| 数据目录 | `%APPDATA%\todo-list` | `~/.config/todo-list` |
| 数据库 | `todos.db`（SQLite，同一 schema） | 同左，可直接搬 |

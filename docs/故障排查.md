# 故障排查

按症状查。每条都注明**怎么判断**和**怎么修**。

---

## A. 应用行为类

### A1. 从菜单点图标"闪退"，窗口一闪而过或不出现

**这不是崩溃。** 大概率是已有实例在托盘里运行，单实例锁让新进程立刻退出。

判断：

```bash
pgrep -af todo-list          # 有输出 = 应用还活着
```

处理：看系统托盘（KDE 通常在右下角，可能要展开箭头），左键单击图标或右键 →
**打开Todo清单**。

彻底退出：托盘右键 → **退出**，或 `pkill -f todo-list`。

详见 [移植原理 §6](移植原理.md)。

### A2. 窗口没有关闭 / 最小化 / 最大化按钮

**补丁没生效。**

判断：`build/app/resources/app.asar` 的 sha256 应为
`94a6712b2f22189a92cccd614a1cd264d245bbded1f8276a9c3b873199c3b0ac`。

处理：

```bash
node scripts/patch.mjs build/app/resources/app.asar    # 看是否报「未找到目标」
```

若报未找到，说明上游改了那段代码 —— 见 [AGENTS.md §3](../AGENTS.md)。

临时兜底：`Alt+F4` 可以关窗口（触发的是同一个 close 事件）。

### A3. 关闭窗口后应用没退出

**设计如此**，不是 bug。关闭 = 缩到托盘。见 [移植原理 §6](移植原理.md)。

### A4. 小组件 / 番茄悬浮窗不显示

Wayland 协议**不允许客户端自行定位窗口或强制置顶**，而这正是这两个功能依赖的。

处理：用 XWayland 启动 —— 启动器的第 2 备选参数已包含 `--ozone-platform=x11`。
也可手动：`~/.local/opt/todo-list/todo-list --ozone-platform=x11`

### A5. 提示 "APPIMAGE env is not defined"

**正常且期望。** 说明没打成 AppImage，更新器据此跳过。
如果打成 AppImage，这个变量会被设置，更新器激活后必然 404 失败（见[移植原理 §3](移植原理.md)）。

## B. 构建流水线类

### B1. `patch.mjs` 报 `EBADF: bad file descriptor, write`

`readAsar()` 用只读模式打开了 asar。必须是 `fs.openSync(path, 'r+')`。

（等长补丁走原地替换，需要写权限。）

### B2. 脚本打印几行就没输出了

`lib.sh` 开着 `set -euo pipefail`，某个命令返回了非零就把脚本带走了。
最常见的是 `timeout` 超时返回 124：

```bash
# 错
timeout 25 "$BIN"; rc=$?
# 对
rc=0; timeout 25 "$BIN" || rc=$?
```

### B3. `pkill` 把脚本自己杀了（verify 无输出就结束）

`pkill -f "<路径>"` 会匹配到调用者自己的命令行（argv 里就含这个路径）。

处理：用 `lib.sh` 里的 `stop_app`，它按进程名找候选再用
`/proc/<pid>/exe` 核实真实路径。

### B4. makepkg 报 `cp: 无法保留...的所有权: 无效的参数`

fakeroot 下 `cp -a` 尝试保留属主失败。

处理：PKGBUILD 里改用

```bash
bsdtar -C "$srcdir/..." -cf - . | bsdtar -C "$pkgdir/..." -xf - --no-same-owner
```

### B5. `unpack.sh` 报「NSIS 里没找到 app-*.7z」

安装器换了壳（不再是 NSIS）。

处理：

```bash
7z l "<安装包>"      # 看第 1 层结构
```

若是 Inno Setup / Squirrel / MSI，需要换解包方式并相应修改 `unpack.sh`；
后续步骤（build / patch / verify）不变。

### B6. `fingerprint.sh` 报读不到 Electron 版本

`strings` 抓不到 `Electron/x.y.z`。可能上游换了 Electron 打包方式。

处理：手动确认版本，例如

```bash
strings "Todo清单.exe" | grep -iE "electron" | head
# 或看 resources/ 里有无版本线索
scripts/fetch-electron.sh <你确认的版本>
```

## C. 打包与安装类

### C1. `sudo pacman -U` 报依赖缺失

包声明的依赖是用 `objdump -p` + `pacman -Qoq` 实测得出的。若上游升级了
Electron 版本，依赖可能变化。

处理：重新生成依赖表

```bash
objdump -p <应用目录>/todo-list | awk '/NEEDED/{print $2}' | sort -u
# 再逐个映射回包名，更新 packaging/PKGBUILD 的 depends=()
```

### C2. 任务栏图标是默认的 Electron 图标

`StartupWMClass` 与窗口实际类名不匹配。应用内执行
`app.setName("Todo清单")`，桌面项已写 `StartupWMClass=Todo清单`。

若仍不对，用 `xprop` 或 compositor 工具查实际 WM_CLASS / app_id 后对齐。

### C2b. 图标是空白 / 文件是 0 字节（已修，勿回退）

**症状**：`/usr/share/icons/hicolor/256x256/apps/todo-list.png` 大小为 0，
`file` 报 `empty`。

**根因**：`scripts/asar.mjs` 的 CLI 入口判断写成了

```js
const isMain = import.meta.url === `file://${process.argv[1]}`;
```

`import.meta.url` 会对路径做**百分号编码**，而本仓库路径含中文
（`Todo清单逆向项目`），编码后与原始 `argv[1]` **永不相等** ⇒
脚本静默什么都不做、**退出码还是 0** ⇒ 重定向出来的图标是空文件，
而打包脚本只看退出码，于是打出了一个图标损坏的包。

**修复**：两边都转成真实文件系统路径再比较

```js
const isMain = process.argv[1] &&
  path.resolve(process.argv[1]) === fileURLToPath(import.meta.url);
```

并给 `build-pkg.sh` / `install-user.sh` 加了大小与类型断言。

**自查**：

```bash
node scripts/asar.mjs cat <app.asar> icon.png | wc -c    # 应 >1000
```

**临时绕过**（不改包、不需要 sudo）：把有效图标放到用户级目录，
XDG 优先级高于 `/usr/share`：

```bash
mkdir -p ~/.local/share/icons/hicolor/256x256/apps
node scripts/asar.mjs cat /opt/todo-list/resources/app.asar icon.png \
  > ~/.local/share/icons/hicolor/256x256/apps/todo-list.png
gtk-update-icon-cache -q -t -f ~/.local/share/icons/hicolor
```

**彻底修复**：重跑 `packaging/build-pkg.sh` 并 `sudo pacman -U` 新包，
然后删掉上面的用户级覆盖。

### C3. 打完包运行异常 / 二进制损坏

检查 PKGBUILD 是否误删了 `options=('!strip')`。**Electron 主程序被 strip
后会损坏**，这是硬性约束。

### C4. 磁盘不够

构建中间产物约：解包 660 MB + 组装 624 MB + makepkg 的 src/pkg 各 624 MB
+ 包 196 MB ≈ 2.7 GB。

处理：

```bash
rm -rf build/ packaging/src packaging/pkg
bash packaging/build-pkg.sh
```

## D. 运行环境类

### D1. `GPU process exited unexpectedly: exit_code=139`

Chromium 的 GPU 子进程段错误（139 = 128+11 = SIGSEGV）。常见于无 `/dev/dri`
或 GPU 驱动异常。Chromium 会自动回退软件渲染，通常不影响使用。

处理：加 `--disable-gpu`（启动器已列备选）。

### D2. `dconf-CRITICAL ... /run/user/1000 只读文件系统`

只出现在**沙箱/容器**里运行的情况。真实桌面会话下不会出现。可忽略。

### D3. `Failed to load module "appmenu-gtk-module"`

可选的 GTK 全局菜单模块未安装，纯外观问题。可忽略，或
`sudo pacman -S appmenu-gtk-module`。

### D4. `Fontconfig warning: ... cache files were generated by a newer version`

字体缓存由更新版本的 fontconfig 生成（通常是降级过 fontconfig）。

处理：`fc-cache -f` 重建缓存。

### D5. `wayland_wp_color_manager: Unable to set image transfer function`

KDE 的色彩管理协议，Chromium 未完整实现该扩展。纯外观，可忽略。

## E. 收集证据的正确姿势

遇到应用层面的问题，**先看它自己的日志**，比猜快得多：

| 日志 | 内容 |
|---|---|
| `~/.config/todo-list/logs/main.log` | 应用 winston 日志（结构化，含时间戳） |
| `~/.config/todo-list/logs/main.old.log` | 上一份（按大小轮转） |
| `~/.config/todo-list/launch.log` | 启动器记录：环境变量、socket、GPU 设备、逐变体尝试结果 |
| `build/verify.log` | 最近一次冒烟测试的完整 stdout/stderr |

注意：**`console.log` 的内容不会进 `main.log`**（那是 winston 专写），
只在 stdout 里。所以 `verify.sh` / 启动器都会把 stdout 单独落盘。

需要看渲染进程的 console 时，用启动器（它设了 `ELECTRON_ENABLE_LOGGING=1`），
或手动：

```bash
ELECTRON_ENABLE_LOGGING=1 ELECTRON_ENABLE_STACK_DUMPING=1 ~/.local/opt/todo-list/todo-list
```

### 界面类问题：直接截图，不要靠推断

```bash
DISPLAY=:1 ~/.local/opt/todo-list/todo-list --ozone-platform=x11 &
sleep 12
PID=$(pgrep -x todo-list | head -1)
ID=$(xdotool search --pid "$PID" | head -1)
import -window "$ID" /tmp/shot.png
```

> 本项目最重要的教训：**「应用能启动」不等于「功能完整」**。
> "窗口没有任何关闭按钮" 这个缺陷躲过了所有日志检查，
> 只有实际看一眼界面才能发现。

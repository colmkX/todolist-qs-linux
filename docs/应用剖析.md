## 4. 关键可行性事实

### 4.1 原生模块自带 Linux 预编译，且是 N-API

`better-sqlite3-multiple-ciphers@13.0.3` 随包携带 8 个平台的预编译模块：

```
prebuilds/linux-x64.node        2,793,792 B
prebuilds/linux-arm64.node      2,449,888 B
prebuilds/linuxmusl-x64.node    3,165,520 B
prebuilds/darwin-*.node / win32-*.node
```

**实测**：`linux-x64.node` 在本机 Node 26 上直接加载成功，导出
`Database, Statement, StatementIterator, Backup, initialize`。
它能跨 Node 大版本加载 ⇒ 是 **N-API**（ABI 稳定）⇒ 在 Electron 43 中同样可用，
**无需 electron-rebuild、无需编译**。

`lib/binding.js` 会按 `process.platform` / `arch` / glibc-musl 自动选中正确的 `.node`。

### 4.2 应用自身的平台分支大多已有降级路径

在 `background.js` 中检索平台判断（已剔除打包进来的第三方库）：

| 位置 | 行为 | Linux 影响 |
|---|---|---|
| `lib/showdesktop.node` 加载 | `if("win32"===platform) try{...}` | 不加载，try/catch 包裹，安全 |
| `setAlwaysOnTop(true,"screen-saver",1)` | `win32 ? 带参 : setAlwaysOnTop(true)` | 有降级分支 |
| 小组件开关 | 仅 `"darwin"===platform` 时禁用 | Linux 走"启用"分支 |
| `app.setAppUserModelId` | 仅 `"win32"` | 跳过 |
| `app.setName("Todo清单")` | 仅 `"linux"` | **已有 Linux 分支** |
| 窗口激活 | `case "linux": "使用Linux特定的窗口激活方法"` | **已有 Linux 分支** |
| `downloadFolderPath` | `app.getPath("documents")` + userData 兜底 | 平台无关 |
| 提醒 | 存 `reminder_time`，渲染进程经 IPC 发 `Notification` | 平台无关 |
| autoUpdater | win32→Nsis / darwin→Mac / **else→AppImage** | 有 Linux 分支，见[移植原理](移植原理.md) |

**结论：作者写代码时是考虑过 Linux 的**，只是从未发布 Linux 版本。

### 4.3 静默失效的一处

主窗口图标的路径是 `path.join(process.resourcesPath, "public", "icon.png")`。
原版安装包的 `resources/public/` 确实存在，但如果移植时只拷 `app.asar`
就会漏掉它 —— 后果是主窗口没有图标。**`build.sh` 已显式复制该目录。**
